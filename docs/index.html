Evidence vs. claims

A model saying “I ran it” is not proof it ran

AI-generated text is never automatically treated as evidence of execution. Every action in every timeline carries an explicit corroboration state — so model narrative can never masquerade as confirmed host activity.

StateMeaning
REQUESTEDA human asked for it
REPORTEDThe model said it happened — narrative, not proof
OBSERVEDA tool-call record exists in the transcript
CORROBORATEDIndependent endpoint or network evidence confirms it
CONTRADICTEDEndpoint evidence shows it did not occur
UNKNOWNInsufficient evidence — stated honestly

Built for hostile hosts

Forensically sound by construction

Every design decision assumes the host is compromised and the evidence is adversarial.

Sealed evidence packages

Every acquisition produces a sealed .adfir package: content-addressed storage, SHA-256 manifest, and a seal covering the entire evidence zone.

Hash-chained custody

Collection and chain-of-custody logs are hash-chained — editing, deleting or forging a single record breaks the chain for everything after it.

Tamper-evident verification

One flipped byte anywhere in the sealed zone fails verify — and it names the exact artifact that was modified.

Hostile-evidence hardened

Suspect binaries are never executed. Symlinks are never followed. ANSI escapes and invisible Unicode are neutralized — your terminal is part of the attack surface.

Agent graph & timeline

Sessions, agents, subagents, tool calls and MCP servers reconstructed into one evidence-linked timeline. Every entry traces to a file, line and hash.

Adversary emulation

agentdfir simulate generates synthetic rogue-agent incidents — orphan agents, cross-session messaging — to validate detections and train responders.

From findings to a story · v1.0

Not a list of alerts. What happened, step by step.

Seven hundred findings are not an answer. The explorer starts at the session, connects the steps into attack chains, shows what led to each step, searches every byte of evidence, and keeps your conclusions in a tamper-evident case file.

Sessions first

One card per session, worst first: what was asked, duration, tool calls, agents, files, destinations, MCP servers, how much the OS confirms, which attack chains hit. Click, and the timeline is that session.

Attack chains

Toxic combinations: injection in a tool result → the agent rewrites its own instructions → a shell runs. Secret read → upload. Orphan agent → config change → tool use. Eight built in, MITRE-mapped, JSON-extensible.

How it happened

Under every finding: the steps in order and, under each, the prompt before it, the tool result the agent had just consumed, the spawn that created the agent. Every node is a real transcript line.

Search everything

Ctrl+K: every event field, every finding, and the raw bytes of every sealed artifact. Literal or regex, seconds over gigabytes, hits jump to the evidence.

Case file

True / false positive / needs review, pinned key evidence, session tags, notes — appended to a hash-chained log outside the sealed evidence, attributed to you, rendered into the PDF and HTML report.

Still forensically sound

Nothing in the tree is inferred without an evidence line. The sealed zone is never written. The one write endpoint is same-origin, loopback only.

Open format

The .adfir evidence package

Self-describing and independently parseable — any forensic tool can read it without AgentDFIR. Raw evidence is sealed once and never touched; analysis output is a regenerable overlay.

  • Lossless. Nothing redacted or rewritten at collection time.
  • Hash-while-copy. Hashes describe exactly the preserved bytes, with torn-read detection for files a live agent is still writing.
  • Every failure recorded. Access denied, size bounds, irregular files — nothing silently dropped.
  • Deploys with your stack. KAPE Target/Module and Velociraptor artifact ship in-repo.

Quick start

One command. Four steps you can also run yourself.

agentdfir run finds every AI agent on this machine, collects all of them into one sealed .adfir package, analyzes it and opens the case explorer. Each step is the same code as the individual command below it.

Install and run — one line per OS

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/efij/AgentDFIR/main/install.sh | sh && ~/.local/bin/agentdfir run

# Windows (PowerShell, x64 or ARM64)
irm https://raw.githubusercontent.com/efij/AgentDFIR/main/install.ps1 | iex; agentdfir run

# already installed, or Homebrew (brew install efij/agentdfir/agentdfir)
agentdfir run
agentdfir run --no-serve        # print the findings and stop (scripts, CI)

Step by step — the same thing, one command per step

# 1. which AI agents are on this machine — never executes them
agentdfir detect

# 2. sealed, hash-chained evidence package
agentdfir collect --product claude --operator "Your Name" --case-id CASE-2026-042

# 3. every analysis stage: detections, MCP audit, provenance
agentdfir analyze CASE-2026-042.adfir

# 4. browse: agent tree, timeline, raw evidence, findings
agentdfir serve CASE-2026-042.adfir --open

Evidence somewhere else?

agentdfir collect --path /mnt/image/Users/x     # a copied home or mounted image
agentdfir collect --import ./kape-tree          # KAPE / Velociraptor / CyLR: every user, every agent
agentdfir collect --docker my-container          # a container, read-only
agentdfir analyze CASE.adfir --endpoint audit.log # auditd / Sysmon as a second witness
agentdfir verify  CASE.adfir                     # prove the package was not modified

Reference

AI agent forensics, answered

What is AI agent forensics?

AI agent forensics is the discipline of collecting, preserving and analyzing the evidence agentic AI tools leave on endpoints — session transcripts, subagent records, MCP configurations, hooks and tool-call logs — so an incident responder can reconstruct who instructed which agent to perform what action, through which tool and identity, and what evidence proves it.

Where does Claude Code store session logs?

Claude Code stores session transcripts as JSONL under ~/.claude/projects/<project>/<session-id>.jsonl, with prompt history in ~/.claude/history.jsonl, settings, hooks, skills, plugins, task state and file-history checkpoints under ~/.claude/, and global configuration (including MCP servers) in ~/.claude.json. AgentDFIR acquires all of them into one sealed package — including subagent and orphan-agent transcripts.

Is a model's own account of its actions evidence?

No. "I executed curl example.com" in model output is a claim — AgentDFIR marks it REPORTED. Only a tool-call record in the transcript upgrades it to OBSERVED, and only independent endpoint or network evidence makes it CORROBORATED. That distinction is the foundation of trustworthy AI-agent forensics.

What does AgentDFIR detect today?

140 deterministic rules including 8 attack chains, every HIGH and CRITICAL one mapped to MITRE ATLAS 5.6 and ATT&CK: orphan agents, cross-agent messaging, destructive and exfiltrating shell commands, agents editing their own instructions or hooks, credentials read from agent config, poisoned or unpinned MCP servers, honeytoken hits, transcript integrity gaps. No LLM in the analysis path — see the detection coverage matrix.

What is an attack chain?

An ordered sequence of agent events that are unremarkable alone and an attack together: instruction-override content in a tool result, then the agent writing its own settings, then a shell command, inside one session within two hours. AgentDFIR matches eight such toxic combinations out of the box, reports each as one finding with the exact steps, and the explorer shows what led to every step.

Do I need to be a forensics expert to use it?

No. agentdfir run does the whole thing — detect, collect, analyze, browse — and the browser explorer shows findings in plain language with the exact transcript line behind each one. The individual commands exist for investigators working on copied homes, disk images, containers or KAPE trees.
