# Case explorer — `agentdfir serve`

```sh
agentdfir serve CASE-42.adfir              # prints http://127.0.0.1:<port>/
agentdfir serve CASE-42.adfir --port 8437 --open
agentdfir run                              # detect → collect → analyze → serve, in one go
agentdfir serve CASE-42.adfir --compare CASE-43.adfir   # adds the Compare view (both packages fully verified)
```

A browser UI for one sealed package, from the same single binary. **Binds 127.0.0.1 only**, loads **no external resources** (CSP `default-src 'none'`, like the HTML report), rejects non-loopback `Host` headers (DNS-rebinding defence), and **never writes to the sealed evidence**. The one thing it writes is the analyst case file, `notes/notes.jsonl`, outside the sealed zone (see below). Every evidence string is sanitized server-side and rendered as text — the analyst's browser is part of the attack surface too.

## Views

Written for someone who is not a security analyst: every severity, confidence and evidence state is said in words, and the rule ids, MITRE mappings and raw references are one click away under *Technical details*. Light and dark themes (follows the OS; the toggle pins one).

- **Overview** (landing) — the answer first: *"4 alerts need action now"*, what was read (conversations, computer, date range, recorded actions), four tiers (**Act now · Serious · Worth a look · Minor or routine**), **Start here** (the most serious kinds of issue, each with how often and in how many conversations), the **accounts** in the case, and whether the evidence is intact.
- **Findings** — grouped by *kind of issue* (rule × severity) instead of listed one by one: 1,237 findings on a real machine are about sixty kinds. Filter by tier, words or account; hide kinds you have finished. A kind opens to:
  - a plain title, one **verdict line** that reads severity and confidence together (*"Act now if real · Needs your check"*), **What happened / Why it matters / Ask yourself**, and *What the detector saw here*;
  - *Time 1 of N* with the conversation, the time and the **account** it ran under;
  - **Most likely start** — the root cause, read off the evidence: your request, an automatic (skill/plugin) message, something the agent read that itself carries injected instructions, or a helper agent. The card it points at is marked **Start** in the story;
  - **The story** — a swimlane diagram in three lanes (*You · The AI agent · Tools & outside world*), one card per evidence line in time order, arrows for every hand-off, gaps longer than ten minutes labelled, the flagged steps in red and numbered, the outside addresses a step reaches. *In short* sums the flagged steps up in one line first. Every card has **Show proof** and **What led to this?**;
  - **What to do**, with **Copy a note for your IT contact**, and **Your decision** — *Real problem · Expected · Detection mistake · Not sure yet* (stored as true positive / benign / false positive / needs review), optionally applied to every other time the same thing happened.
- **Activity** — conversations on the left, named by what the person first asked (skill and harness text skipped), each with its account; on the right, what happened, oldest first: when, who (*You · AI agent · Helper agent · Tool · Automatic*), what, flagged or not. Show *Everything · What was asked · Agent actions · Tool answers · Helper agents started · Only flagged*; words, account and time-range filters; a busy-ness strip to jump to a minute. Background bookkeeping records are left out. Keyboard: `j`/`k`.
- **Proof** (a side panel, from anywhere) — the record in plain fields (when, who, conversation, account, command, file, address, result, evidence status), *What stands out* (safety prompts off, a helper agent wrote this, the tool reported an error or a refused login, invisible characters), the findings on it, *Mark as key evidence*, *What led to this*, and the exact sealed log line.
- **Protect** — what can be done about this case's findings, in four groups: *Fix now* (config that is unsafe right now: unpinned MCP packages, auto-approve lists), *Prevented by guardrails* (which pack stops it recurring), *Needs a person* (the exact step: rotate the key, review the file) and *Not fixable by settings*. The guardrail table shows each pack's level (ask or block, switchable), friction and how many findings it covers, pre-ticks the two zero-friction packs, and, on the machine the case came from, applies them: *Preview changes* lists every file with its summary and exact diff, *Apply* writes them (backup per file, hash-chained ledger, same code path as the CLI), and *Changes made on this computer* has *Undo* per change and *Undo all*. Findings you marked *Expected* or *Detection mistake* leave the counts. Once guardrails are applied, each rule shows *N since <date>* and each pack *In place* or *Removed since*. Writes are same-origin only and carry a per-process token the page gets on load, so no other page or site can trigger them; a case from another computer gets the `agentdfir mitigate --select … --apply` command to copy and run there. See [mitigate.md](mitigate.md).
- **Coverage** — what the case can and cannot show, from `normalized/coverage.json` (see [investigation-graph.md](investigation-graph.md)). The headline says how many agent actions an independent record confirms. Three columns: **What we know**, **What we don’t know**, **What to collect next** (each item with *Proof* buttons for the evidence it cites). Below: a strip of every independent source (endpoint telemetry, cloud audit, host witness, shell history) drawn over the time it covers, under the agents’ activity coloured by how much of it the computer’s records cover; per kind of action, how many were confirmed, disproved or not checked and why; **Actions with a second witness** (each opens the side-by-side comparison below); clock problems; orphan agents, missing parents and tool answers without their call; silences inside conversations and log-integrity problems. A gap is said as “nothing recorded”, never “something hidden”.
- **Who did what** (lineage) — on every finding (under *What to do*), on every conversation (*Who did what* in Activity and in AI conversations) and for the whole case (More › Who did what): Person (AI account) → AI agent → Helper agents → Agent actions → Programs the computer ran → Addresses, files, cloud, as a left-to-right SVG graph drawn in the page (no library). Line colour is the evidence state (written in the log · confirmed · partly confirmed · records disagree · claimed only), the label is the link (*asked*, *started*, *did*, *ran as*, *connected to*…) with the match strength for correlated links; the finding’s own steps are outlined in red. Click a box or a line for its basis and its source references: an event opens its proof, a sealed line opens in the raw-line pane, an imported-telemetry reference is named (it is not part of the sealed evidence). The finding and conversation graphs are built by the lineage package’s own scoping (`agentdfir lineage --finding/--session`) bounded at 240 boxes / 600 lines, the whole-case one is the stored `normalized/lineage.json` cut to the same bound; at most 40 boxes per column are drawn. Whenever anything is left out the panel says **Truncated** and points to `agentdfir lineage`.
- **Second witness** (side-by-side) — in the proof panel of any action that an independent record confirmed, partly confirmed or contradicted, and from Coverage: *What the agent’s log says* next to *What the computer’s process log / file log / network log / web proxy log / DNS log / cloud audit log / script-block record recorded*, with the match basis, score, strength (*Strong / Good / Weak match*, the correlate package’s HIGH / MEDIUM / LOW), the time difference against the allowed window, the event’s witness note, and what that process did next (records with the same pid). The pairings come from `detections/corroboration.json` (`matches`), written by `analyze --endpoint`.
- **More**
  - **Command palette** — `Cmd+K` / `Ctrl+K`, or `/` when you are not typing, opens a search box over the page. With nothing typed it lists recent searches, the findings to look at first, every view and a few actions. As you type it fuzzy-matches views, the More sections, findings (by plain title or rule id) and conversations instantly, and shows up to six matching actions from the evidence (`/api/search`, events only) a moment later. `↑` `↓` or `Tab` move, `↵` opens, `Cmd/Ctrl+↵` runs the full search below, `esc` clears then closes. The header box and, on a phone, the search button open the same palette. Secrets are masked in every result.
  - **Search everything** — from the palette with `Cmd/Ctrl+↵`, or More › Search everything. Literal or RE2, optional case, over every event, every finding and — when ticked — the raw bytes of every sealed artifact (bounded to 20 s / 500 hits).
  - **AI conversations** — conversations that never touched an agent: chats from AI-service account exports (ChatGPT, Claude.ai, DeepSeek, Gemini Apps; [ai-service-exports.md](ai-service-exports.md)) and AI pages from opt-in browser history ([browser-ai-sessions.md](browser-ai-sessions.md)). Each is listed by the name the evidence records (the export’s conversation title; the browser group’s *ChatGPT conversation "…"*, never a raw `web:…` id) with its service and an evidence-class badge: **Provider export** or **Browser history — visits only, no content**. Export conversations show their messages in order; messages on a branch the person moved away from (a regenerated answer, an edited question) are kept and marked *Other branch*, and a fork the export does not resolve (DeepSeek) is marked as such; the list shows how many messages each conversation has on other branches. Browser conversations list their visits and say that no message text exists. The same readable names are used in Activity.
  - **Extensions & agent plugins** — `detections/extensions.json` ([extensions-plugins.md](extensions-plugins.md)): its findings, then editor extensions (editor, id, version, install time, recorded source, starts with the editor, code checked), agent plugins (hooks, MCP servers), plugin marketplaces, skills and agent definitions, and what could not be read.
  - **Bookmarks** — *Bookmark* on a finding and *Mark as key evidence* in the proof panel both write a pin to the case file (below), so they are hash-chained, carry the operator and time, and appear in the report’s pinned items. This view lists bookmarked findings, key evidence and **saved filters**. *Save this filter* (Findings) and *Save this view* (Activity) store a named filter in this browser only (`localStorage`, every access guarded; nothing is saved when the browser refuses); saved filters are also in the palette.
  - **Compare cases** — with `serve <case> --compare <other>`: the second package is checked exactly as `agentdfir correlate-cases <case> <other>` checks it (full verification of both, both analyzed by this version; [investigation-graph.md](investigation-graph.md) §3) and the view shows both cases with their integrity, every shared item (account, incident indicator, secret by fingerprint, outside address, plugin, tool definition, instruction file, conversation or agent id, computer name) with count and first/last seen per case, identity links, and a timeline strip and table of the shared items. A refused second case is shown with the reasons (also printed in the terminal); the explorer still serves the first case. Without `--compare` the view gives the command.
  - **Plugin (MCP) activity** — every MCP tool call in time order: time, account, plugin, tool, *what the agent sent* (read out of the sealed line) and *what came back* (the matching tool result), filterable per plugin.
  - **Plugins installed** — one row per plugin: used by, account, runs on this computer or online, fixed version or not, what it is, where it is set.
  - **Memory files** — instruction and memory files, with the lines an agent wrote and why (copied from a tool answer, after your request…).
  - **Cross-check** — the OS/gateway corroboration summary when `correlate` ran, or the command to run it.
  - **Agent map** — conversations → main agents → helpers for the conversations with findings; agents with no known parent outlined in red.
  - **About the evidence** — computer, collection time, integrity (quick check on open, *Re-check every file now* for the full re-hash), signature, version.

Evidence states in words: *Written in the agent’s own log* (OBSERVED), *Claimed by the agent* (REPORTED), *Confirmed by the computer’s own records* (CORROBORATED), *The computer’s records disagree* (CONTRADICTED), *Not cross-checked* (UNKNOWN). The stored values are unchanged.

## Accounts

One person often runs agents under more than one login — a work Claude seat and a personal ChatGPT plan, or two Claude config directories. Every record, conversation, finding and plugin carries the account it ran under. The login is not on the events; it is read from the product's own settings in each profile directory that was collected — `~/.claude.json` (`oauthAccount`: email, organisation) for a Claude profile, `<CODEX_HOME>/auth.json` (the `id_token` claims: email, ChatGPT plan) for Codex — and an event belongs to the profile directory its transcript sits in. Claude desktop (Cowork) sessions stored under a Claude account id are matched to that account. Only the identity is read; tokens and keys never leave the server. A profile whose login file was not collected is shown as *login not recorded*.

## The investigation tree

For an attack-chain finding the root's children are the matched steps in order. For any other finding they are the events its evidence references resolve to. Under every event node, the explorer adds what led there, each one a real transcript line:

| Role | What it is |
|---|---|
| tool result the agent had just consumed | the nearest earlier `tool_result` for the same agent — the input the model acted on |
| instruction delivered to this subagent | the `agent_message` a parent sent to a subagent |
| spawned this agent | the `agent_spawn` whose task id is this agent |
| human prompt before this | the nearest earlier `human_prompt` in the session |
| result returned to the agent | the `tool_result` of this tool call |

Nothing in the tree is inferred without an evidence line. *What led here* on any node fetches its own context (`/api/chain?event=<id>`), so the analyst can walk back as far as the evidence goes.

## The case file (`notes/notes.jsonl`)

Verdicts, notes, pins and tags are appended to `<pkg>/notes/notes.jsonl` as a hash chain (each record carries the SHA-256 of the previous line, like the custody log), with the OS user and a UTC timestamp. Editing, deleting or reordering a record breaks the chain and the explorer says so. The file lives outside the sealed zone, so `verify` still passes and the evidence is untouched. `report --format html|pdf|json` renders the case file as an *Analyst Investigation* section: verdicts per finding, pinned evidence with its raw reference, session tags, notes.

`POST /api/notes` is the only write endpoint. It requires the `X-AgentDFIR-Notes: 1` header, a loopback `Origin` (or none) and a same-origin `Sec-Fetch-Site`, so no page in another tab can forge entries. Everything else stays `GET`.

## API

All JSON, loopback only: `/api/case`, `/api/sessions`, `/api/events?session=&agent=&type=&state=&q=&from=&to=&account=&mcp=1|<server>&flagged=1&nometa=1&sort=time&offset=&limit=` (rows carry `account`, `flags`, and for MCP calls `sent` / `answer`), `/api/accounts`, `/api/event/{id}`, `/api/raw?artifact=&offset=`, `/api/findings`, `/api/chain?finding=<i>` | `?event=<id>`, `/api/search?q=&mode=text|regex&case=1&scope=events,findings,raw&limit=`, `/api/notes` (GET; POST as above), `/api/graph`, `/api/buckets`, `/api/extras`, `/api/mitigations` (the Protect view), `POST /api/mitigations/plan|apply|revert` (same-origin + `X-AgentDFIR-Mitigate: <token>` from the GET; same machine only), `/api/coverage`, `/api/lineage[?finding=<index>|?session=<id>]`, `/api/witness[?event=<id>]`, `/api/conversations`, `/api/conversation?session=<id>`, `/api/extensions`, `/api/compare`. `/api/sessions` rows carry an optional `label` (the evidence’s own session name, when it has one). Events are not held in memory: `<pkg>/index/events.idx` records each event's byte offset in `normalized/events.jsonl` plus the fields the lists filter on, and the full event is read by offset when a detail view asks for it. The index is derived data — outside the sealed zone, not covered by `SHA256SUMS`, safe to delete, rebuilt on load when missing or stale. There is no event cap; `--max-events` is accepted and ignored.

### The investigation routes

They read derived files through the same overlay reader as every other overlay read (gzip or plain) and never fail on an old package: a missing or unreadable file, or one in a format this version does not read (reported as UNSUPPORTED), answers `{"available": false, "reason": …, "regenerate": "agentdfir analyze <case>"}` and the view shows that command.

| Route | Reads | Bounds and checks |
|---|---|---|
| `/api/coverage` | `normalized/coverage.json` (`agentdfir.coverage/1` only) | every string sanitized; each evidence reference resolved to its event and to one of this case’s artifacts (never used as a path), at most 2,000 |
| `/api/lineage` | no parameter: `normalized/lineage.json`; `finding` / `session`: built on demand by `lineage.Build` over that scope’s sessions | `finding` must be a plain index into the findings, `session` an id present in the case, otherwise 404; both together 400; 240 boxes / 600 lines; labels, attributes, bases and references sanitized; the last 32 scoped graphs cached |
| `/api/witness` | `detections/corroboration.json` `matches` | `event` must be an event of the case (404 otherwise); the list is bounded at 500 |
| `/api/conversations`, `/api/conversation` | the index and `normalized/entities.jsonl` | products `chatgpt`, `claude-ai`, `deepseek`, `gemini-apps`, `browser` only (other sessions 404); 1,000 messages per conversation, texts cut at 4,000 characters |
| `/api/extensions` | `detections/extensions.json` | every list cut at 2,000 entries (`<list>_omitted` counts the rest), sanitized |
| `/api/compare` | the report `crosscase.Run` produced at start-up | sanitized |

What the explorer does not do: it never runs `correlate-cases` against a package other than the one given with `--compare`, never imports telemetry (that is `analyze --endpoint`), and never builds a whole-case lineage graph past the panel bound; `agentdfir gaps`, `agentdfir lineage` and `agentdfir correlate-cases` remain the full outputs.

Multi-user, hosted or remote access is deliberately out of scope for the open-source tool.
