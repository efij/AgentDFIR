# Prove it offline — `agentdfir selfcheck --offline`

AgentDFIR says *nothing is fetched, nothing is executed, nothing is sent*.
`selfcheck --offline` lets anyone confirm that on their own machine, without
trusting the claim: it runs the AgentDFIR binary as the subject of a collection
and analysis, under the strongest containment the OS offers, and reports whether
the subject opened any network socket, spawned any child process, or wrote
anything outside the case and state directories.

```sh
agentdfir selfcheck --offline            # human report, exit non-zero on any violation
agentdfir selfcheck --offline --json     # machine-readable
agentdfir selfcheck --offline --profile ~/real-home   # collect a real profile instead of a synthetic one
agentdfir selfcheck --offline --no-canary
```

By default the subject runs on a **synthetic profile** generated by
`agentdfir simulate` in a temporary directory; your real home is never touched
unless you pass `--profile`.

## Levels of proof

The report always states which level it reached, because the guarantee is only
as strong as the containment the platform provides:

| Level | How | Where |
|---|---|---|
| **kernel-enforced** | the OS refuses network, child processes and out-of-tree writes outright | macOS (`sandbox-exec`), Linux (`unshare --net`) |
| **traced** | every network and process syscall the subject makes is recorded and inspected | Linux with `strace` |
| **in-process** | the binary's own guard records and refuses any non-loopback dial | Windows, and anywhere the above are absent |

On macOS the subject runs under a generated `sandbox-exec` profile that denies
`network*`, denies `process-exec*` except the subject re-executing itself, and
denies `file-write*` except under the temporary case directory. `sandbox-exec` is
deprecated by Apple but present on every macOS. On Linux the subject runs in a
network namespace (`unshare --net`) and, when `strace` is available, is traced for
`connect`/`sendto` to any non-loopback address and for any `execve` after the
subject itself. Where no kernel containment is available the **in-process guard**
is the floor: an environment variable makes the binary replace its HTTP transport
and DNS resolver with ones that record and refuse every non-loopback connection,
backed by a build-time test that the collect and analyze paths import no process
-spawning code.

## The connectivity canary

A sandbox that is silently not enforcing would let a check pass while proving
nothing. Before trusting a kernel level, `selfcheck` runs a **canary** *inside*
the sandbox — a tiny mode of the same binary (`agentdfir selfcheck --canary`)
that tries to reach a public address. If the canary connects, the sandbox is not
enforcing and the result is downgraded to in-process, never reported as a pass on
kernel enforcement. The canary runs only inside the sandbox; `selfcheck` itself
sends nothing. `--no-canary` skips it.

## Output

```
AgentDFIR offline self-check
Platform:     darwin
Containment:  sandbox-exec
Proof level:  kernel-enforced
Canary:       BLOCKED — the sandbox is enforcing
Subject:      exit 3 (…run --no-serve --new …)
Network:      0 non-loopback dial(s) observed
Result:       PASS — nothing was sent, nothing was executed, nothing was written outside the case.
```

The command exits non-zero on any violation, so it works as a gate. AgentDFIR's
CI runs `selfcheck --offline` on Linux on every change, and on macOS in
`sandbox-exec` mode, so a regression that opened a socket or spawned a process
fails the build.
